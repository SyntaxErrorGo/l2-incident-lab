# Runbook: диагностика ошибок создания заказа

## 1. Первичная проверка

1. Зафиксировать HTTP-код и время ошибки.
2. Скопировать request_id.
3. Проверить, массовая ли проблема, в Grafana.
4. Найти запрос в Kibana.
5. Проверить результат операции в PostgreSQL.

## 2. Поиск запроса в Kibana

request_id : "ID"
and method : "POST"
and path : "/api/orders"

## 3. Проверка заказа в PostgreSQL

SELECT id, product, status, request_id, created_at
FROM orders
WHERE request_id = 'ID';

## 4. Разбор сценариев

### 502

- Nginx не смог обратиться к upstream.
- Проверить логи Nginx.
- Убедиться, что POST не дошёл до backend.
- Проверить состояние backend-контейнера.
- Записи в БД обычно нет.

### 504

- Backend получил запрос, но не ответил в пределах таймаута.
- Проверить логи Nginx и backend по request_id.
- Обязательно проверить БД: операция могла завершиться.
- Не повторять POST без проверки — возможен дубль.

### 429

- Проверить Retry-After.
- Проверить источник и количество запросов.
- Не выполнять бесконечные повторные запросы.

### 500

- Найти исключение в backend-логах.
- Проверить влияние на другие запросы.
- Передать разработчикам request_id и фрагмент ошибки.

## 5. Эскалация

Передать:

- время инцидента;
- HTTP-код;
- request_id;
- масштаб;
- найденные логи;
- результат проверки БД;
- уже выполненные действия.
